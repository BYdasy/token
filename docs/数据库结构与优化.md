# Token 数据库结构与优化记录

更新日期：2026-10-14。本文记录本次实际改造及验收边界，与[维护与数据库迁移](维护与数据库迁移.md)配套使用。

## 本轮范围与结果

用户明确授权将当前测试项目整理为新的 Token 项目：统一项目命名，合并重复结构，清除旧版本数据及代码关联，不再建设旧版本兼容层。该要求优先于原优化方案中“保留历史订阅、旧通知、旧代理、旧协议”的分阶段建议。本文不把这次测试项目清理方案视为其他已有业务库的通用升级策略。

| 项目 | 改造前 | 本轮结果 |
| --- | --- | --- |
| 数据库结构 | 103 张表、1218 列 | 88 张表、1073 列，净减少 15 张表、145 列 |
| 项目目录 | Credits 命名 | `E:/exp/token`，活跃目录为 `token-server`、`token-admin`、`token-user` |
| Java 包、应用名、数据库 | `org.credits`、`credits` | `org.token`、`token` |
| 管理站入口 | `/credits/` | `/token/`；用户站仍为 `/` |
| 业务 API 与端口 | `/api/compute`、9091 | 保持现行接口前缀与端口 |
| 账号与密码 | 原有效账号及密码 | 没有改名、重置密码或替换密码散列；数据库连接账号、密码值不因库名调整而改变 |

原方案提出的 98、95、92 张表是按历史兼容前提设计的阶段目标。本轮按用户的新项目要求退役额外旧结构，最终结构为 88 张表；不是为了达到某个表数而合并不同业务事实。

新增 `admin_security`；16 张被替代或退役的表退出当前结构。`compute_subscription_quote` 改名为 `compute_product_quote`，只是更正现行业务名称，不计入减表数量。表数不包含验证库、临时迁移对象或仓库外的备份。

实际交付文件：

- [完整优化 SQL](../token-server/docs/20261014_01_token_optimization.sql)：固定目标库和对象，按本次核验前提编写的整文件迁移。
- [当前纯结构](../token-server/docs/token-schema.sql)：88 张表的结构基线，不含账号、密码、订单、资金或密钥数据；仅供空库建结构及比对，不能覆盖已有业务库。
- [隔离测试结构](../token-server/src/test/resources/token-schema.sql)：测试读取同一套当前结构，不再从历史增量 SQL 拼装夹具。

## M1–M7 的实际落地

| 方案项 | 实际结构与代码调整 | 保留的语义及边界 |
| --- | --- | --- |
| M1 管理员安全状态合并 | `account_totp`、`admin_login_attempt`、`admin_login_security_state` 归入 `admin_security`，以 `admin_uid` 为主键，每个有效管理员有安全记录。 | 保留 TOTP 密文、启用与强制开关、已消费计数、绑定时间、失败次数、锁定截止时间和 `invalid_before`。`login_attempt_updated_at` 与普通 `updated_at` 独立，不能互相替代。验证码防重放、失败计数、账号锁及会话撤销逻辑继续生效。 |
| M2 管理员资料归并 | `ad_detail` 退出；电话、联系邮箱、备注、国家、累计登录次数、最近登录 IP/客户端及资料时间并入 `ad_master`。主账号保留用户名、密码、角色、状态、头像、标签、语言与展示时区。 | 联系邮箱使用 `contact_email`，不复用原整数邮件限额 `email`。`profile_updated_at` 保存原资料/登录摘要更新时间，不冒充真实登录发生时间。在线状态由会话推导，失败锁定由 `admin_security` 管理。 |
| M3 授权范围标记归并 | `compute_admin_scope_state` 退出，标记移入 `ad_master.scope_configured_at`；多根明细仍在 `compute_admin_member_scope`。 | 当前实现中，标记为空表示全局；标记非空且无根节点表示禁止访问；有根节点按子树并集过滤。不能把无法映射的旧受限账号放大为全局。标记与明细由同一事务更新，超级角色仍走显式规则。 |
| M4 通用配置归一 | `compute_setting` 迁入 `system_setting` 后退出。沿用已核实的实际配置键，不统一机械增加前缀；同名冲突会阻止迁移。增加逐键 `revision`，值扩为 `LONGTEXT`，更新时间使用微秒精度。 | 原字符串、JSON 数值精度、空值和更新时间保留。迁入业务键默认不公开、不可从通用编辑入口直接修改；公开读取及领域写入均由明确权限、白名单和业务校验控制。不能把资金、安全、代理判断放入展示缓存。 |
| M5 单行配置归一 | 奖励配置移到 `compute.reward.configuration`，自动通知配置移到 `notification.automation.configuration`，均存于 `system_setting`；原两张配置表退出。 | 每个领域单独一行。JSON 文档分别保留 `configuration` 与 `activatedAt` / `collectionStartedAt`，并保留原版本、修改人和时间。更新按旧 `revision` 条件写入并递增，普通设置不能绕过奖励或通知规则。音频配置、告警运行状态、刷新租约与关系锁未并入普通配置。 |
| M6 旧会员通知退出 | 按用户明确的新项目要求，删除 `compute_member_notice` 及旧通知读写入口；当前内容、接收关系和系统消息投递路径继续使用。 | 本轮没有执行原方案的旧通知兼容导入，不保留旧通知编号或旧链接，不添加仅为兼容而设的 `legacy_notice_id`、重复阅读状态。管理员收件箱与会员内容保持不同身份空间；当前消息投递幂等表继续保留。 |
| M7 旧代理体系退出 | 删除 `compute_admin_agent`、`compute_agent_closure`、`compute_agent_line`，以及会员、分组、内容中的旧 `agent_id` / `owner_agent_id` 依赖。真实邀请事实统一为 `compute_member.inviter_id`，管理范围使用 `compute_admin_member_scope`。 | 保留分组与内容的 `owner_member_id`、内容的 `target_member_id` 等现行归属。不能把旧代理编号直接当作会员编号。仍有未处理旧归属时迁移守卫拒绝继续；先处理子表外键再退出父表，没有关闭外键检查来强删依赖。 |

`admin_login_session` 与 `compute_member_session` 仍独立保存会话。保留凭据摘要、撤销记录和空闲期限；管理员的 `absolute_expires_at` 继续约束已有 JWT 或 TOTP 绑定短凭据，普通空闲会话不新增统一绝对时长。方案建议的全账号绝对期限会改变持续活跃用户的登录行为，且未给出合理期限，本轮不凭空设定。单账号有效会话由账号锁、事务及实时安全复核保证，没有给管理员编号简单加唯一索引来排斥历史会话。

## 业务字段与旧代码清理

| 范围 | 本轮处理 |
| --- | --- |
| 管理员旧字段 | 退出 `ad_master.permission` 的旧范围回退，以及 `secret_key`、`action`、`level`、`amount`、`edit`、原整数限额 `email`。`ad_detail` 的重复用户名、启停、在线、失败计数和旧限额不再进入新账号结构。 |
| GPU 产品与报价 | 当前产品仅 GPU。报价表及服务改为产品报价命名，现有用户报价 API 仍为 `/api/compute/user/orders/quote`。删除产品年率、旧等级门槛、供应商/模型绑定、订阅排序和价格列；当前成交仍保存固定日率、报价、购买金额/份数和永久累计限购依据。 |
| 产品订单 | 删除旧订阅升级链、订阅金额和年率/计息基准等退出实现的列；报价快照列改为 `product_quote_json`，金额品牌字段改为 `purchase_amount_token`。清理旧测试订单及其精确关联的结算/幂等返回记录，不重新计算保留的 GPU 订单金额或收益。首次报价表改名时丢弃旧短期报价，重复迁移不清空新报价。 |
| VIP 执行 | 只保留当前即时点击执行：本金不扣、不冻，收益即时入账，动画和明细延时单独运行。删除旧日息协议引擎、旧本金冻结/释放路径、旧并发协议和 `SETTLE_AUTO` 调度。旧引擎记录按已授权范围清理后，退出 `engine_version`、`income_mode`、`execution_mode` 等不再分支的字段。 |
| VIP 配置与模型 | `auto_provider_ids` 成为唯一供应商绑定，非空 JSON，空数组表示不绑定；删除 `auto_model_ids` 及其 NULL 回退。旧额度、周期、日息、并发和执行模式配置退出，当前每日次数、冷却、单次收益、动画、明细延时及 VIP 周期规则保留。`compute_model_usage` 旧用量结构退出。 |
| 供应商规范化 | 删除模型表的冗余 `provider` 文本，供应商事实由非空 `provider_id` 表达。界面所需供应商名称从 `compute_provider` 联表返回，删除列不等于删除显示能力。 |
| 活动概率 | 奖位只使用 `probability DECIMAL(13,6) NOT NULL DEFAULT 0`，表示相对权重；支持 0 至 1000000、最多 6 位小数，0 不参与抽取，不按百分比归一化。删除独立 `weight` 列和运行时回退。宝箱 JSON 的 `chestRanges[].weight` 是另一种区间权重，继续保留。 |
| 费率与品牌金额 | 删除已停用的 `low_amount_threshold`、`low_amount_fee` 配置列；保留当前原币费率、固定费用和订单快照。签到金额列改为 `reward_token`，展示接口使用 `usdPerToken`，不因改名改变钱包币种或资金数值。 |
| 管理员通知 | `system_notification` 仅存站内消息；清理已核实的旧 POPUP 数据后删除 `display_type`。实时 SSE 的 `NotificationPushEvent.displayType` 仍支持消息与弹窗，不将临时弹窗写回收件箱。 |
| 奖励与邀请 | 删除旧 `compute_team_reward` 及旧奖励中心 legacy 配置/展示；保留当前奖励事件、接收人分项及到账事实。团队深度只读取当前 `teamSupportedDepth`，去掉旧 `teamDepth` 配置回退。 |
| 外部支付协议 | 旧 `compute_mcag_deposit`、`compute_mcag_collection_receipt` 在核实为空、没有外键或当前入账依赖后退出；非空会被守卫拒绝。当前逐笔充值与归集协议保留，前端核查只使用 `DEPOSIT_ORDER` / `COLLECTION_BATCH`，移除旧查询入口和猜测会员身份的回退。 |

两端同步删除订阅入口、旧订单筛选和表单字段、VIP 旧结算提示及对应 DTO。项目目录、包名、路径、缓存名、API 品牌字段与部署片段统一到 Token；保留仍有效的 `@exp/*` 工作区包和 `EXP_*` 环境变量标识，避免破坏正常工具链和部署覆盖项。

Crypto 是独立外部项目。已登记的商户、凭证、客户身份、公钥、钱包和地址归属不能由本地品牌改名推导新值。本轮保留外部既有身份、密钥及固定业务事实；关闭旧身份字符串解析前，依据真实地址归属补齐并核对 `compute_mcag_customer_identity`，不把旧客户标识拆分成未经验证的会员编号。

表和字段注释按现行业务补正，包括 VIP 可用算力余额门槛、系统时区、LINK 公司资源和固定 USD 计价来源。注释变更保留实际字段类型、默认值、排序规则及索引，没有用旧文档快照反向覆盖当前结构。

实际数据库为 MySQL 8.0.12；本轮不依赖该版本不能强制执行的 CHECK 约束，也不套用更新版本的即时删列语法。金额范围、合法业务状态、并发与幂等继续由当前服务事务及真实唯一约束共同保证。DDL 会隐式提交，不能宣称整批结构变更可由普通事务回滚。

## 明确保留的不同粒度事实

| 结构 | 保留原因 |
| --- | --- |
| 钱包与账本 | 钱包是当前可用/冻结余额，账本是逐次变更及唯一事件；两者在同一资金事务维护，余额不能替代过程事实。 |
| 充值、提款、划转与代付任务 | 审核、冻结、双钱包变更、外部发单租约和未知结果恢复有不同生命周期，不合成万能订单或一个状态字段。 |
| 固定财务快照与实时行情 | 成交计价、手续费、净额及原始报价必须可重放，行情缓存不能重算旧订单。财务快照保留业务类型维度。 |
| 支付历史地址、当前指针、代次与客户身份 | 分别表达永久归属、当前选择、真实链上的分配代次及外呼前身份登记；换地址不覆盖历史归属。 |
| 外部事件与同步游标 | 事件可以乱序；游标表示连续处理进度，不能直接取最大已见事件号。 |
| 订单/执行与结算明细 | 一笔订单可以多次结算；保留期次唯一键、真实已付收益和结算事实，展示进度不等于资金到账。 |
| 奖励事件与奖励分项 | 一次来源可能产生多个接收人或零奖励，零奖励也要保留已处理事实，不能只从分项反推事件。 |
| 活动资格、轮次状态、发放凭据及参与记录 | 充值阶梯与邀请人数资格的防重粒度不同；可用次数不能替代已发凭据，无奖及待兑奖参与也不一定有资金流水。 |
| 内容接收、版本确认、翻译任务及语言执行项 | 阅读关系、每版本确认和逐语言重试分别有独立主键和生命周期，不能压成一份无版本 JSON。 |
| 运行锁、租约与配置 | 关系版本、地址互斥、行情刷新、告警持续状态和任务运行记录承担并发控制，不并入低频设置。 |

当前请求号、订单号、资金事件唯一键、报价复核、账号/会员锁和重试返回快照继续生效。保留的幂等响应只同步退出字段和 Token 字段名，不更换请求号、不改变资金数值、不按当前行情重算。

## 权限、多语言与旧输入收敛

权限以 [当前权限清单](v23-permissions.json)、服务端 `PermissionCodes` 和前端常量为准，共 128 个可授权叶子。原角色权限只按已核实的固定逐项映射一次性转存；运行时移除旧 610 等业务码和父节点授权，不能按数字前缀放大权限。普通角色字符串不能伪造 `super`，超级角色标记及受保护账号规则保留。

中英文业务基线集中到 `docs/i18n/current-{server,admin,user}-{zh,en}.json`；两端加载当前基线，不再叠加历史版本字典。服务端、管理端、用户端分别对应 type 1、5、7，通知模板 type 6 仍独立。新增词条补缺不覆盖人工非空译文，词条修改与 `i18n.translations.revision` 更新按事务处理。

历史版本 SQL、翻译生成器、被替代字典和相关测试装配链已清理；测试通过 `TokenTestSchema` 读取当前纯结构，保留真实非空、外键、生成列和唯一性。翻译审计保留 `Audit-TranslationKeys.mjs` 与 `TranslationFiniteReferences.mjs`，只检查当前输入及源码；权限审计使用 `Audit-Permissions.mjs`。上游许可证、现用框架依赖与有效素材保持原用途，不把它们按旧文件日期批量删除。
