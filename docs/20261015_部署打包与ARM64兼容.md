本次修改日期：2026-10-15。修改打包规则、图片原生依赖与配置诊断；没有执行数据库 SQL、真实支付、自动打包或服务器部署。

## 商户配置

当前属性前缀是 `token.mcag`。外置文件即使被 `spring.config.additional-location` 成功加载，`credits.mcag` 也不会绑定到当前配置。用户已确认将顶层 `credits:` 改为 `token:` 后连接正常，原文件路径和启动参数无需更换，原商户身份、凭证及四个密钥文件继续沿用。

本轮移除了未配置时的 `http://127.0.0.1:8080` 默认值；未接入显示空地址。外置配置加载后若仍含旧前缀，启动会明确提示修改，避免继续使用另一份配置。启用后的字段错误只报告配置字段和修复方向，不回显实际凭证、密钥或包含口令的 URL。

原命令可以继续使用：

```sh
java -jar /www/wwwroot/data/token-server.jar \
  --spring.config.additional-location=file:/www/wwwroot/data/config/application-mcag.yml
```

## 图片处理与 ARM64

旧 `org.sejda.imageio:webp-imageio:0.1.6` 根据 Linux/64 位选取 `native/linux/64/libwebp-imageio.so`，实际文件是 AMD64 ELF；在 ARM64 JVM 中不能加载，文件存在或增加文件权限都不能解决架构不匹配。

已替换为 [usefulness/webp-imageio](https://github.com/usefulness/webp-imageio) `0.11.0`。核验下载的实际 JAR：Linux `aarch64` 文件为 ELF machine 183，`x86_64` 为 62；包含 Windows x64 文件。对应 Kotlin stdlib 固定为 2.4.0，避免依赖管理降级。JPEG/PNG 仍编码为 WebP，透明度及 `exp.image.webp-quality` / `EXP_WEBP_QUALITY` 保留。

上传时的 WebP 尺寸检查、解码和分享预览固定走 TwelveMonkeys 纯 Java 读取器。保留原格式的 GIF/WebP 复核真实内容，保存的 MIME 使用受控格式；伪造扩展名、非法图片及失败上传不留下文件或素材记录。JNI 写入错误会报告 CPU 架构、libc、依赖版本及临时目录的排查方向。

其他原生依赖也做了检查：当前 gRPC Netty 同时包含 Linux ARM64 与 AMD64 文件；移除了 Google Translate 传递引入、只包含 Linux AMD64 的可选 Conscrypt 2.5.2 包，Java 17 继续使用标准 JSSE TLS。没有关闭证书或主机名校验。

Linux 部署需使用匹配 CPU 的 Java 17；本次 WebP 二进制要求 **glibc 2.27 或更新版本**，未承诺兼容 Alpine/musl。可在服务器只读核对：

```sh
uname -m
java -XshowSettings:properties -version
getconf GNU_LIBC_VERSION
```

若原生库临时目录不可写或禁止加载，创建由服务账号拥有、可写且允许原生库加载的专用目录，再将 `-Dcom.luciad.imageio.webp.tmpdir=/www/wwwroot/data/tmp/webp` 放在 `-jar` **之前**。该参数只指定提取目录，不能修复 CPU 或 libc 不兼容。图片/文件存储路径和 `EXP_IMAGE_PATH`、`EXP_FILE_PATH` 优先级保持不变。

## 打包内容

- 服务端资源处理和主 JAR 双层排除 README、CHANGELOG、AGENTS、示例 YAML 和 sourcemap，避免旧 `target/classes` 残留说明进入新 JAR。实际运行配置、`META-INF/spring.factories` 及许可证保留。
- `prepare-package` 只清理本次输出目录的 `lib`，随后重新复制当前运行依赖，避免新旧 WebP 或 TLS 包混放；仍为主 JAR + 同级 lib 的瘦包。
- 管理端和用户端生产构建使用统一 public 资源过滤，排除开发说明、类型声明及 sourcemap。图片、业务 PDF/Markdown、PWA、PDF.js 和许可证保持原相对路径，源码说明不删除。

当前静态资源会排除用户端 `images/vora/README.md`，以及管理端 `tinymce/CHANGELOG.md`、`tinymce/langs/README.md`、`tinymce/tinymce.d.ts`。打包后可从项目根目录检查：

```powershell
node scripts/Audit-PackageContents.mjs --dist
```

本轮由用户按原流程打包。服务器更新时一起替换同一批主 JAR 和完整 `lib`，不要将新依赖覆盖叠加到旧目录；尤其不能继续加载旧 `webp-imageio-0.1.6.jar`。前端更新使用新构建目录，避免旧说明文件仍留在网站根目录。
