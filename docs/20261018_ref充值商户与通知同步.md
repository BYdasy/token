## 已同步内容

| 范围 | 当前行为 |
| --- | --- |
| 充值归集展示 | 保存 Crypto 单笔充值返回的 `collection_reason_code`。未关联批次且原因为 `BELOW_SWEEP_THRESHOLD` 时，显示“未达到最低归集金额”；其余保留待分批状态。已有批次、关联错误和同步异常优先，不按单笔充值金额猜测归集门槛。 |
| 商户记录 | 归集批次、归集交易、系统操作日志及能量相关六类列表统一页码、总数和 10/20/50/100 条分页。标签切换保留各自筛选及分页；查询失败保留上次成功结果并支持重试原目标。精确编号查询仍按详情处理。 |
| 大页查询 | 超过 20 条时通过 10 条的小页读取，核对总数、页码、数量及业务号唯一性后合并；任一段失败则整页失败，避免加密报文过大或显示残缺结果。原游标和支付协议不变。 |
| 商户用户名 | 按当前商户及环境的永久客户身份映射批量查询会员，支持带代次的客户号，不从客户号字符串猜 UID，也不显示上游提供的未经本地核实的用户名。 |
| 自动通知 | 修复数字订单 ID 与通知来源键比较时的 MySQL 排序规则冲突；精确保留大整数 ID。失败日志仅含错误类型、SQLState、错误码等诊断信息，不输出凭据、SQL 参数或消息正文。 |
| 通知管理 | 渠道、模板、Telegram 绑定改为服务端分页，默认 20 条，支持 20/50/100 条；搜索、删除尾页、失败重试及安全渠道选项均有对应处理。 |
| 单模板测试 | 启用模板可以填写示例变量、选择语言并预览，向一个启用渠道内的一个有效绑定发送一条带 `[TEST]` 的消息。内容变更后须更新预览；不读取真实订单，不批量发送，不自动重试。 |

本轮没有新权限。通知查看、配置和测试继续使用现有叶子权限及代理范围，测试沿用 `60702/super`；独立渠道选项仅返回编号、名称和渠道类型。资金账本、充值入账、提款与归集执行规则未变。
