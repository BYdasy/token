# 逐笔充值与地址缓存

更新日期：2026-10-14。本文描述当前 Token 的逐笔充值、独立归集和地址复用。完整通信、权限及部署说明见 [MCAG 接入与维护](20260917_MCAG商户端接入开发文档.md)。

## 数据库与配置

当前数据库为 `token`，业务 API 为 `/api/compute`。现有实例使用 [本轮完整优化脚本](20261014_01_token_optimization.sql)，当前空库结构见 [token-schema.sql](token-schema.sql)，执行要求见 [维护与数据库迁移](../../docs/维护与数据库迁移.md)。应用启动不自动执行数据库迁移。

`token.mcag.address-cache-seconds` 默认 60 秒，运行时限制在 1～300 秒。它是最近权威状态核验的复用窗口，不是外部网关监听租期。运行时币网映射读取数据库。

## 逐笔订单与归集

- 充值权威来源是 `deposit-orders/query` 的 `SINGLE_RECEIPT` 订单；`DEPOSIT_ORDER` 事件只触发重新查单，不直接信任回调正文金额。
- 商户、环境、订单号、收款凭据、转账事件及币网、交易哈希、交易内定位共同防重。同一交易哈希可以包含多笔合法转账。
- 仅订单及链状态确认、确认数达标、终局满足、风险 `CLEAR`、收款决定 `CREDITED`，且会员归属与金额等校验通过时入账。测试会员、未知归属、停用地址或缺报价保留待处理或核查事实。
- 原币按资产精度保留，最高 30 位小数；钱包按入账时成功行情固定为 USD，记账金额沿用 8 位精度。不能截断原币事实，不能按新行情重算已入账金额。
- `record_id` 是可展示的本地订单，`local_deposit_id` 才是已完成钱包加款的标记。链重组只标核查，重新确认不重复发放资金、奖励或通知。
- `RECEIPT_SWEEP` 与 `credit_status=INDEPENDENT` 只记录归集状态。摘要包含已入账及未入账收款金额，不能按归集总额给用户加款。
- 后台归集只读取 `view=summary`，校验版本、数量和金额守恒；界面需要明细时使用 `view=receipts` 分页读取，不让后台为大批次展开全部明细。
- 逐笔订单响应使用 `items/has_more`，下一页 `before_id` 取本页最后的 `order_id`。订单、归集、共享事件各自持久保存位置，处理失败不推进；不受支持事件持久登记忽略。

## 地址复用与归属

已核验地址按商户、环境、用户钱包、网关资产和映射版本查询。每次仍实时校验本地账号、测试身份、币种、网络、充值开关和钱包支持；在有效窗口内才复用已核验结果，过期核验失败不继续展示旧成功地址。

首次或过期请求在资金事务外调用网关；进程内合并与数据库短租约防止同目标并发申请。商户资产能力在进程内按核验窗口共享，减少逐用户重复查询，返回后仍复核本地币网、配置和映射版本。

网关主地址变化时追加归属记录并更新当前展示指针。收到尚未打开币网的可信订单时，只有完整客户身份、地址编号、币网映射及会员共同确认后才补全归属；不能凭地址文本猜测用户。停用与入账共用会员锁，锁后重新检查地址状态。

取址响应包含 `currency/network/walletType/addressId/monitoringReady/status/verifiedAt`。只有地址 `status=ACTIVE` 且 `monitoringReady=true` 才返回可展示的地址和 memo；监听未就绪时这两个值为空，未就绪结果最多缓存两秒。不同目标钱包使用独立客户身份，地址轮换代次也持久保存；不能按 `ACTIVE` 状态单独判断监听已就绪。

## 核查与验证

充值核查重新查询权威逐笔订单后进入同一资金事务；归集核查只更新归集，不创建充值。缺价订单持久排队，行情恢复后先重新查单，再按原幂等规则处理。外呼不持有资金行锁。

当前定向测试包括 `ComputeMcagReceiptTest`、`ComputeMcagAddressCacheTest`、`ComputeMcagEventFlowTest`、`ComputeMcagCollectionTest`、`ComputeMcagBatchReaderTest`、`ComputeMcagDepositReconciliationTest` 和 `ComputeMcagDepositStatusTest`。这些测试使用隔离数据库及远程桩，重点覆盖原币精度、重复事件、归集零加款、地址并发与停用、缺价重试和核查范围。
