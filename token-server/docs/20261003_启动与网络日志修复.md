# Mapper 启动故障、网络日志与法币刷新修复

本次修改代码，不需要执行 SQL，不修改已有支付配置、密钥、资金记录或汇率历史快照。

## 启动时 Mapper 未注册

`ComputeRecordMapper is not known to the MybatisPlusMapperRegistry` 是本次启动失败的根因。之前分层整理后的 `ComputeData` 构造器直接调用 `SqlSessionTemplate.getMapper`，此时 Spring 的 `MapperFactoryBean` 尚未把接口注册到 MyBatis。翻译服务、系统消息、安全依赖和 Web 服务启动失败都是同一异常的连锁结果。

现在通过 Spring 注入 `ComputeRecordMapper`，其他持久层辅助对象通过 `BeanFactory.getBean` 取得 Mapper，确保初始化完成后再使用。继续复用应用的 MyBatis-Plus、MPJ、数据源、插件与事务，不另建生产 SqlSessionFactory。

修复前已用隔离 Spring 启动测试复现同一异常。修复后，默认配置和启用 MCAG 业务 Bean 的配置均实际启动内嵌 Web 服务，并逐一检查生产 Mapper 注册、Spring 实例复用和 MPJ 联表方法。测试使用 H2、禁用调度与 Redis，替换 MCAG 客户端及翻译任务恢复依赖，不代表已验证生产数据库、真实密钥或远端网络。

## MCAG 偶发网络失败

用户已确认错误偶发，随后恢复。既有补拉保留持久位置并自动退避重试，恢复后继续同步。日志中的业务码 `502` 和 `HTTP=0` 不能直接判定远端返回了 HTTP 502；旧实现直到正文接收完成才记录状态，正文接收中断也可能显示 0。

新增安全诊断：按异常类型区分 DNS、连接失败、连接超时、TLS、完整请求超时、正文超时、连接关闭及中断，并记录请求耗时。响应头到达即记录 HTTP 状态；随后读取正文失败会标记 `RESPONSE_BODY`。不输出第三方响应正文、原异常消息、请求地址或凭据。

保留连接 5 秒、完整请求 15 秒的期限及原退避规则；写请求不自行重复发起。未修改支付状态判断、游标、幂等入账或退款条件。此次增加可定位的证据，未声称已经修复服务器网络。

## 无文件名图片请求

`/api/material/image/` 是目录地址，缺少文件名。此前它进入 Spring 静态资源处理，再被通用异常处理误报为系统 500。

现在缺失静态资源按空 404 返回；真实存储 IO 故障仍为 500 并保留 ERROR。两端共享头像、品牌、图片选择及币网图标入口排除空白和同源精确素材目录地址，使用原有占位或默认图片；合法文件和外链保持原样。没有批量改写数据库中的图片配置。仅凭旧日志无法确定哪一条线上配置发起了该请求。

## Frankfurter 每 12 小时自动刷新

法币自动刷新间隔改为 12 小时，失败继续使用最近成功值，下次自动尝试仍遵循该间隔。加密币行情保持每 30 分钟刷新。调度器每 30 分钟检查资格，通过已有刷新表的持久时间与条件更新领取执行资格；升级前留下的短截止时间、进程重启或多个节点都不能绕过法币间隔。

后台手动刷新保留原限频和失联执行的租约恢复。刷新中途配置变更时丢弃旧版本返回值，并允许下次调度按新版本重取一次；取得资格后恢复 12 小时周期。无需修改表结构或手动更新刷新时间。
