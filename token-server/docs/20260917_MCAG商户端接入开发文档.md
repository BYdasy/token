# Token 的 MCAG 接入与维护

更新日期：2026-10-14。本文按当前 Token 服务端实现整理，适用于逐笔充值、独立归集、商户账户查询和可靠提款。外部网关的可用资产、权限和状态以当前已验签的响应为准。

## 1. 系统边界

用户和管理员的浏览器只调用 Token 服务端。Token 保存商户通信密钥，负责会员归属、钱包、资金事务、权限、幂等和核查；MCAG 负责链上地址、确认、出款、归集及商户费用。归集目标和网关侧策略由外部平台管理。

充值以 `deposit-orders/query` 返回的 `SINGLE_RECEIPT` 订单为权威。`collection-batches/query` 返回的 `RECEIPT_SWEEP` 只用于归集查询，不产生用户加款。充值入账和归集完成是两个独立事实。

当前配置只接受 `LIVE`。本地运行也可能连接真实链，隔离测试使用远程桩，不通过启用真实网关验证资金功能。

## 2. 凭证与 JOSE

平台需提供网关地址、`merchant_id`、`credential_id`、有效 Scope、平台签名公钥和平台加密公钥。商户保管自己的签名私钥和解密私钥，向平台登记对应公钥。`credential_id` 是平台凭证标识，与 JWK 的 `kid` 不同。

商户本地的两对密钥加平台两个公钥共六个文件都有用途；运行客户端读取商户两个私钥及平台两个公钥。不能用平台私钥替代商户私钥，也不能为排查配置问题重新生成已有密钥。私钥、数据库密码和完整通信正文不进入前端、日志或 Git。

网关接口使用 `POST /v1/...`，请求和响应的 Content-Type 为 `application/jose`。请求正文是紧凑 JWE，内层 JWS 使用 `RS256`，外层使用 `RSA-OAEP-256` 和 `A256GCM`，RSA 至少 2048 位。业务 JSON 位于已签名 claims 的 `body` 中，不能直接作为 HTTP 正文发送。

当前客户端复用方式：

```java
var result = client.request(
    "deposit-orders/query",
    Map.of("order_id", orderId, "limit", 1)
);
```

`operation` 不带 `/v1/`。客户端生成请求 `jti` 和 120 秒有效期，绑定商户、环境、凭证、`http_path` 与响应 `in_reply_to`；收到响应后先解密验签，再使用 `body`。回调同样验证完整身份、路径和时间窗。

三个位置的 `kid` 不可混用：

| 消息 | 内层 JWS header.kid | 外层 JWE header.kid | claims.kid |
| --- | --- | --- | --- |
| 商户请求平台 | 商户签名凭证 | 平台加密公钥 | 商户签名凭证 |
| 平台响应或回调 | 平台签名公钥 | 商户解密私钥对应公钥 | 商户签名凭证 |

远端地址要求 HTTPS，仅 loopback 允许 HTTP；不接受重定向。连接期限 5 秒，完整响应期限 15 秒，正文上限 128 KiB。HTTP 429 只触发共享请求冷却，未验签错误正文不能证明订单拒绝或成为退款依据。

重试必须重新生成通信信封，保留原业务请求号和参数。提款创建超时后先查询原单；不因 HTTP 5xx、超时、`UNKNOWN` 或 `REVIEW` 换单号再次出款，也不据此退冻。

## 3. 金额、身份与时间

- 原币金额用十进制字符串和 `BigDecimal` 处理。逐笔充值保存原币完整事实，接受的精度由已验签资产 `decimals` 决定，最高 30 位小数；不能在查单时先截为 8 位。超出允许精度或本地可表示范围的金额进入核查。
- 钱包固定以 USD 记账，使用既有 USDT 编码。充值按入账时成功行情保存固定 USD 快照；提款冻结、扣款和退款沿用同一报价快照。原币金额和 USD 记账金额分别保存，不按当前行情重算已入账资金。
- 本地客户标识以 `token_<memberId>_compute`、`token_<memberId>_project` 或提款用的 `token_<memberId>_earnings` 表达会员与钱包。充值地址轮换时还带持久代次后缀；服务端根据认证身份生成并核对持久身份映射，不能由客户端指定他人会员编号。
- `asset_id` 与 `network_id` 是网关身份；本地币网映射从数据库读取，不根据币种符号或资产 ID 外观猜测。网关资产与本地 symbol、网络、开关必须一致。
- 业务时间使用 UTC；JOSE 的 `iat/exp` 使用 Unix 秒。Token 的自然日规则仍由系统业务时区控制。

## 4. 逐笔充值与归集

`deposit-orders/query` 精确查询使用 `order_id`，返回唯一匹配订单。自动补拉每页最多 20 条，以 `purpose=CUSTOMER_DEPOSIT` 筛选。响应使用 `items/has_more`，下一页 `before_id` 取本页最后的 `order_id`，不读取 `next_cursor`。

入账前同时核对：

1. 当前商户及 `LIVE` 环境、`CUSTOMER_DEPOSIT`、`SINGLE_RECEIPT`、订单版本和事件资源。
2. 客户、地址、资产、网络、收款凭据、转账事件、交易哈希及交易内定位，金额与已有订单保持一致。
3. 订单和链状态均确认、确认数达标、`finality_satisfied=true`、`risk_status=CLEAR`、`credit_decision=CREDITED`。
4. 会员归属、测试身份和地址停用状态；未知归属、测试会员、缺报价等情况保留核查或待处理事实。

在完整事务中串行复核会员与入账幂等，保存充值单、固定计价、钱包流水、奖励和通知等应一起成功的事实。`compute_mcag_deposit_order.local_deposit_id` 表示已完成钱包入账；`record_id` 只是本地可展示订单。重复事件、重复补拉和重新确认不会再次加款。已入账后链重组只标核查，不自动扣回余额。

同一交易哈希可以含多笔合法转账。订单号、收款凭据、转账事件以及币网、哈希、交易内定位共同防重，不能仅按 `tx_hash` 去重。

归集后台只请求 `view=summary`：必须是 `accounting_model=RECEIPT_SWEEP`、`credit_status=INDEPENDENT`，核对 `receipt_count`、版本和 `credited_amount + uncredited_amount = amount`。后台摘要不接受内嵌明细或明细分页字段。归集补拉每页最多 5 批，使用独立 `batch_before_id`，并核对 `next_cursor` 与本页末项一致。

用户充值归集与服务费归集均可被跟踪；归集总额可能包含尚未达到充值入账条件的收款，不能据此创建充值或给用户加款。界面需要收款明细时，通过商户归集接口使用 `view=receipts` 和明细游标按页读取。归集失败或核查只更新归集状态。

地址缓存、归属补全和补拉细节见 [逐笔充值与地址缓存](20260920_逐笔充值与地址缓存.md)。

## 5. 提款与核查

用户仅从收益钱包提款，必须使用本人已绑定、有效、币网匹配的 `addressId` 并验证支付密码。报价预览、提交复核、原请求号幂等和会员行锁共同约束实际扣款；不提供临时输入地址绕过绑定的用户入口。

本地审核通过后建立持久发单任务。MCAG 收到的出款金额为用户申请原币净额，Token 内部冻结和结算使用报价时固定的 USD 金额。不能把 Token 估值作为链上原币金额，也不能重复扣取已确认的手续费。

本地审核与网关出款审核分别存在：网关 `REVIEW`、`UNKNOWN`、提交结果不明及链上处理中继续保留冻结。只有符合当前终态规则的权威结果才能扣款或退款。新信封重试沿用原 `merchant_order_id`、报价和业务参数。

按交易哈希补查只提交线索，不指定用户到账金额。超级管理员通过当前 TOTP 后提交 `requestId/assetId/networkId/txHash/address`，可选 `transferLocator`。网关创建核查任务不代表已发现充值或已入账；最终仍由权威逐笔订单进入原有入账事务。

## 6. 事件和回调

三个补拉位置分别保存：共享事件 `after_sequence`、逐笔订单 `order_before_id`、归集摘要 `batch_before_id`。事件默认每 15 秒最多拉取 20 条，序号必须严格连续；处理完成并持久保存后才推进。订单和归集补拉不改变共享事件位置，失败保留原位置并退避。

- `resource_type=DEPOSIT_ORDER` 只接受 `deposit.credited`、`deposit.review`、`deposit.reconfirmed`，随后重新查询订单。
- 当前归集事件要求 `resource_type=COLLECTION_BATCH`，重新查询并验证 `RECEIPT_SWEEP` 摘要，只更新归集。
- 提款事件交给同一提款查询和结算流程。
- 不受支持的事件持久登记忽略，不从 payload 加款，也不阻塞后续连续事件。

回调入口均为 POST JOSE：

- `/api/compute/callbacks/deposit`
- `/api/compute/callbacks/deposit-exception`
- `/api/compute/callbacks/payout`
- `/api/compute/callbacks/payout-exception`

这些入口使用独立 JOSE 认证，不使用会员或管理员 Bearer。按实际登记路径验签，持久处理成功后返回 2xx；验签、查单或事务失败返回非 2xx。`event_id` 防消息重放，资源版本防旧状态覆盖，业务唯一约束防重复资金变更，三者用途不同。公网回调不可用时仍由事件补拉完成同步。

## 7. 当前本地接口与权限

Token 普通接口位于 `/api/compute`，使用现有 `code/message/data` 响应。会员接口只操作本人；管理员接口使用当前数字叶子权限或真实超级角色。以下网关管理查询还要求全局范围，不能以行范围检查代替接口授权。

| 本地路径（省略 `/api/compute`） | 方法 | 当前要求与用途 |
| --- | --- | --- |
| `/user/deposit-address` | GET | 本人币网和钱包取址；返回地址、监控就绪及地址状态 |
| `/user/deposits/sync` | POST | `depositId` 指逐笔 `order_id`，复核本人、币网及钱包后查单 |
| `/admin/gateway/deposits/status` | GET | `30100/super`；`page/pageSize` 分页核查列表 |
| `/admin/gateway/payouts/status` | GET | `30200/super`；`page/pageSize` 分页核查列表 |
| `/admin/gateway/payouts/{reference}` | GET | `30200/30201/super`；按原订单查询同步 |
| `/admin/gateway/reconciliation` | POST | `super` 与 TOTP；`kind/reference/remark/code` 核查 |
| `/admin/gateway/payouts/{reference}/cancel` | POST | `super` 与 TOTP；仅满足未发出及权威查无单等条件时撤销 |
| `/admin/gateway/deposits/recheck-options` | GET | `super`；读取可补查资产 |
| `/admin/gateway/deposits/recheck` | POST | `super` 与 TOTP；按交易线索创建核查任务 |
| `/admin/gateway/collection-balance` | GET | `super`；读取当前商户钱包摘要和服务费账户 |
| `/admin/gateway/merchant-funding` | GET | `super`；读取当前外部归集目标摘要 |

商户页面已经由 `/api/compute/admin/merchant` 提供受控代理：

| 页面或能力 | 当前权限（另允许 `super`） | 网关数据来源 |
| --- | --- | --- |
| 归集及归集交易 | `80100` | `collection-batches/query`、`sweeps/query` |
| 商户钱包、归集目标和账单 | `80200` | `merchant-wallets/query`、`collection-destinations/query`、`merchant-bills/query` |
| 服务费账户、地址和流水 | `80201` | `service-fee/account/query`、`service-fee/addresses/query`、`service-fee/ledger/query` |
| 通知及投递记录 | `80202` | `notifications/query`、`notifications/attempts/query` |
| 资源账户和订单 | `80203` | `energy-account/query`、`resource-orders/query` |
| 核查记录 | `80204` | `deposit-rechecks/query` |
| 连接检查、资产及规则同步 | `80300` | `assets/query`、`merchant-policies/query` 等受控检查 |

服务端只转发当前查询白名单字段，应用全局范围和响应脱敏。钱包、归集目标和服务费账户使用摘要；资源订单使用当前 `CURRENT` 视图。刷新、核查和配置同步按各自控制器与 Service 的权限校验，浏览器不直接构造任意网关操作。

网关 Scope 与 Token 数字权限是两层独立授权。启用对应功能前核对平台凭证是否具备资产、地址、充值、事件、提款、余额及核查等所需 Scope；缺少 Scope 应修正凭证授权，不降低本地校验。

## 8. 外部配置和部署

工作目录为 `token-server`。外部配置 `.local/mcag/application-mcag-local.yml` 不提交 Git；以下仅为占位模板：

```yaml
token:
  mcag:
    enabled: false
    poll-enabled: true
    poll-delay-ms: 15000
    address-cache-seconds: 60
    base-url: https://gateway.example.com
    merchant-id: <平台分配的商户ID>
    environment: LIVE
    credential-id: <平台登记的凭证ID>
    signing-key-file: .local/mcag/merchant-signing.jwk
    decryption-key-file: .local/mcag/merchant-encryption.jwk
    platform-signing-key-file: .local/mcag/platform-signing.public.jwk
    platform-encryption-key-file: .local/mcag/platform-encryption.public.jwk
```

通过 `SPRING_CONFIG_ADDITIONAL_LOCATION=file:.local/mcag/application-mcag-local.yml` 加载。当前唯一前缀是 `token.mcag`，外置 YAML 顶层必须为 `token:`；旧的 `credits.mcag` 会在读取外置文件后明确阻止启动，不能把文件加载成功误当成旧前缀已转换。未配置网关地址时管理端显示空值，不再默认展示 `127.0.0.1:8080`。启用时校验地址、商户/凭证、LIVE 环境及四个 JWK 文件，并只输出有问题的配置字段名，不打印配置值或密钥路径。

生产外置文件可用 `--spring.config.additional-location=file:/www/wwwroot/data/config/application-mcag.yml` 加载，该参数应放在 `java -jar token-server.jar` 后面。实际文件不存在时应让启动报错，不使用 `optional:` 掩盖缺失。命令行 `--token.mcag.*` 和环境变量 `TOKEN_MCAG_*` 仍可覆盖 YAML，发现显示值不符时一并检查；修改文件后需重启 Java 进程。相对密钥路径按实际运行目录解析，生产建议采用绝对路径。运行时币网映射来自当前数据库，`channels` 仅供首次手动同步识别旧通道编码；完成凭证、资产及通道核对后再启用网关，不要覆盖主应用数据库配置或重新生成已有密钥。

Token 服务端默认 9091；管理端和用户端各自通过本站 `/api` 代理访问。发布保持 `token-server.jar` 与同级 `lib` 配套，并重启 Java 进程。MCAG 调度使用独立三线程，避免恢复成通用单线程轮询。

网关是外部独立项目，其部署、数据库、RPC 和平台密钥由对应项目管理；本地 Token 维护不修改它。
