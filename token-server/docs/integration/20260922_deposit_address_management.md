# 充值地址管理与本地停用

本次按用户指定的方案在 Token 内实现，未修改独立的 Crypto 项目。管理员在「用户 → 充值地址管理」按用户名、入账钱包和链获取地址、分页查询历史或停用地址。

## 身份与缓存

- `compute_mcag_address` 永久保留真实地址及资金归属；不删除停用地址。
- `compute_mcag_address_current` 保存每币网已核验地址及当前状态，仍使用原有 1～300 秒缓存（默认 60 秒）。有效且就绪的本地缓存直接返回；过期、未就绪、映射变更或核验失败不得向用户展示可用地址。后台历史列表始终直接读取本地记录，不请求 Crypto。
- `compute_mcag_address_generation` 按商户、环境、用户、入账钱包、远端真实链保存当前代次，同链所有币种共用。第一代保留 `token_3_project`；停用后下一次依次使用 `token_3_project_1`、`token_3_project_2`。COMPUTE 和 PROJECT 钱包始终分开。
- `compute_mcag_customer_identity` 在任何远端生成外呼前永久登记客户编号归属。新代次回调只依据这张表识别会员与钱包，不拆字符串猜测；旧基础编号保留严格的历史兼容校验。
- EVM 的 BSC、ETH、POL 各保留真实链的代次指针；相同用户、钱包和代次可由 Crypto 复用地址组，各链监听就绪状态分别核验。

生成仍使用既有签名 `customer-addresses/get-or-create` 协议。服务端保持用户锁下的短事务与多实例租约，外呼不持有资金锁。返回结果必须同时通过当前代次、客户归属、商户环境、资产链映射、就绪状态及租约校验；停用前发出的迟到结果不能重新激活旧地址。接口重试及并发使用同一已持久化代次，不为重试更换编号。

## 停用与到账

停用是 Token 本地行为，不关闭 Crypto 的链上监听。管理员停用某个地址时，同用户、钱包和真实链下该地址的各币种记录一起停用，并使相应缓存和外呼租约失效。

停用后收到的权威订单仅记录为「停用地址充值」，不增加用户余额；已经成功入账的历史资金不回扣、不再次加款。迟到的另一币种订单补全同一地址归属时继承停用标记。旧地址永久参与提款地址排除和资金审计。

## 部署与授权

先备份并验证数据库可恢复，再由用户手动执行 `20260922_88_deposit_address_management.sql`，随后发布匹配代码。SQL 添加两张身份/代次表和历史地址停用字段，补中英文翻译及以下叶子权限，不改已有角色权限字符串：

| 权限 | 能力 |
| --- | --- |
| 610114 | 查看充值地址 |
| 610115 | 生成充值地址 |
| 610116 | 停用充值地址 |

页面、按钮及接口分别按叶子权限控制，`super` 可管理；查询和操作同时遵守实时代理行范围。普通账号使用页面需要授予查看权限，再按需授予生成、停用权限。

定向验证使用 `ComputeDepositAddressManagementTest`、`ComputeMcagAddressCacheTest` 以及原有充值收款测试，全部为隔离 H2 和远程桩。未执行真实数据库迁移、真实地址生成或支付。
